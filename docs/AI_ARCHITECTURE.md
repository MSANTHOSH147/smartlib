# SmartLib AI — Technical Architecture Specification

## 1. System Overview
SmartLib AI is a multi-model, retrieval-augmented intelligence layer embedded within the SmartLib library management ecosystem. It combines generative reasoning (Google Gemini, Groq), semantic vector search (Qdrant), transactional catalog state (MySQL), Reciprocal Rank Fusion (RRF), multi-signal reranking, user memory, and Model Context Protocol (MCP) integration.

## 2. End-to-End Request Lifecycle
1. **Transport & Authentication**: Client initiates `POST /api/ai/chat`. `JwtAuthenticationFilter` validates the bearer token and populates the `SecurityContext`.
2. **Rate Limiting**: `AiRateLimiter` enforces a per-user sliding window limit (default 10 req/min).
3. **Trace Generation**: `AiController` assigns a unique `UUID` correlation request ID and initiates high-precision monotonic timing (`System.nanoTime()`).
4. **Memory Injection**: Active user memories for the authenticated user are retrieved from MySQL, sanitized as inert text, and injected within `<USER_MEMORY>...</USER_MEMORY>` system context.
5. **Model Orchestration**: `SmartLibAiOrchestrator` invokes the active provider (`AiModelRouter`). The LLM decides whether to answer directly or call registered SmartLib tools.
6. **Tool Execution**: Tools run within a bounded loop (max 4 iterations). Personal tools derive identity exclusively from `SecurityContext`.
7. **Hybrid Retrieval & Reranking**: If search tools execute:
   - MySQL retrieves lexical matches.
   - Qdrant retrieves semantic matches (768d Cosine).
   - RRF merges candidate ranks into Top 20.
   - `DeterministicBookReranker` scores candidates across 5 normalized signals and selects the Top 5.
   - MySQL hydrates live physical copy and shelf location data.
8. **Web Grounding**: External inquiries trigger Gemini Google Search grounding. Web citations are transformed into typed `AiSource` objects.
9. **Telemetry & Response**: `AiRequestTrace` records subsystem latencies and tool executions. Micrometer increments operational counters. The controller attaches `X-AI-Request-Id` and returns `AiChatResponse`.

## 3. Provider Routing & Fault Tolerance
`AiModelRouter` provides resilient multi-model routing:
- **Primary Provider**: Google Gemini (`gemini-3.8-flash` or `gemini-2.5-flash`).
- **Fallback Provider**: Groq Cloud (`llama-3.3-70b-versatile`).
- **Circuit Breaker**: On HTTP 429 (rate limit), 5xx, or network timeout, the primary provider enters a 60-second cooldown period, routing subsequent traffic seamlessly to Groq.

---

## 4. Retrieval-Augmented Generation (RAG) & Search Pipeline
### Step A: Dual-Channel Retrieval
- **Lexical**: MySQL SQL matching title, author, category, and description.
- **Semantic**: Qdrant vector search matching 768-dimensional text embeddings generated by `gemini-embedding-2`.

### Step B: Reciprocal Rank Fusion (RRF)
Combines lexical rank ($r_{\text{lex}}$) and semantic rank ($r_{\text{sem}}$) with constant $k=60$:
$$\text{RRF Score} = \frac{1}{60 + r_{\text{lex}}} + \frac{1}{60 + r_{\text{sem}}}$$
The Top 20 candidate books from RRF advance to reranking.

### Step C: Multi-Signal Deterministic Reranking
$$\text{rerankScore} = (\text{semanticScore} \times 0.40) + (\text{lexicalScore} \times 0.25) + (\text{titleMatch} \times 0.15) + (\text{authorMatch} \times 0.10) + (\text{categoryMatch} \times 0.10)$$
- Title, author, and category matches evaluate exact word-boundary tokens.
- Signals are dynamically normalized if individual signals are absent.
- The Top 5 final results are returned and hydrated from MySQL.

## 5. User Memory Architecture
- **Inert Data Boundary**: Memories are encapsulated in inert tags: `<USER_MEMORY>...</USER_MEMORY>`.
- **System Guard**: Prompt instructions explicitly mandate that memory contents cannot override system instructions, alter authorization boundaries, or execute commands.
- **Privacy & User Scoping**: Memories are stored in MySQL table `user_memories` with foreign key `user_id`. Users can view and delete (`forgetMyMemory`) their saved memories at any time.

---

## 6. Model Context Protocol (MCP) Integration
- Exposes read-only catalog tools, resources (`smartlib://...`), and standardized prompts via TypeScript stdio server.
- Derives user identity strictly from `SMARTLIB_AUTH_TOKEN`. Rejects client-supplied `userId`, `memberId`, or `email` parameters.
- Maintains MySQL and Spring Boot REST APIs as the single authoritative source of truth.

---

## 7. Observability & Telemetry Architecture
- **No Secret Logging**: Prompts, LLM completion text, and user memories are strictly excluded from logs and traces.
- **Trace Fields**: Request ID, provider, model, fallback flag, grounding flag, memory flag, tool count, latency breakdown, error category, success status.
- **Metrics**: Actuator Micrometer counters and timers registered with safe categorical tags (`provider`, `model`, `success`, `error_category`, `tool`).
